# Эмулятор командной оболочки (вариант №16)

Практическая работа №1 по дисциплине «Конфигурационное управление».

## Общее описание

Проект представляет собой эмулятор командной оболочки UNIX-подобной
операционной системы. Эмулятор работает в форме консольного
приложения (CLI): он показывает приглашение к вводу, разбирает
введённую строку на команду и аргументы и выполняет её.

Реализованные этапы:

1. **REPL** — прототип с диалогом и командами-заглушками.
2. **Конфигурация** — параметры командной строки, журналирование
   событий в формате XML и выполнение стартовых скриптов.
3. **VFS** — загрузка виртуальной файловой системы из ZIP-архива
   целиком в оперативную память.
4. **Основные команды** — рабочая логика `ls` и `cd`, а также
   команды `history` и `echo`.

## Описание всех функций и настроек

### Параметры командной строки

| Параметр | Назначение | По умолчанию |
|----------|-----------|--------------|
| `--vfs ПУТЬ` | Путь к физическому расположению VFS (ZIP-архив) | не задан |
| `--log ПУТЬ` | Путь к лог-файлу в формате XML | журнал не ведётся |
| `--script ПУТЬ` | Путь к стартовому скрипту эмулятора | не задан |

При запуске эмулятор печатает отладочный список всех заданных
параметров.

### Команды

| Команда | Назначение | Аргументы |
|---------|-----------|-----------|
| `ls` | Содержимое каталога VFS | `[-l] [путь]` |
| `cd` | Смена текущего каталога | `[путь]`, без него — корень |
| `echo` | Вывод аргументов через пробел | Произвольные |
| `history` | История введённых команд | `[число записей]` |
| `exit` | Завершение работы эмулятора | Отсутствуют |

Подробности режимов:

* `ls` без аргументов показывает текущий каталог, с путём — указанный
  каталог или сам файл; ключ `-l` добавляет права доступа и размер
  в байтах, например `-rw-r--r--      60 report.txt`.
* `cd` понимает абсолютные и относительные пути, а также имена `.`
  и `..`; подъём выше корня VFS оставляет путь в корне.
* `echo` без аргументов печатает пустую строку.
* `history` нумерует команды в порядке ввода; аргумент ограничивает
  вывод последними записями. В историю попадают и ошибочные команды.

### Приглашение к вводу

Приглашение содержит имя VFS и текущий каталог: `deep:/home/user$ `.
Имя берётся из имени файла образа VFS без расширения; если параметр
`--vfs` не задан, используется значение `vfs`.

### Журнал событий

Если задан параметр `--log`, каждый вызов команды сохраняется в
XML-файл. Журнал перезаписывается после каждого события, поэтому
остаётся корректным XML-документом даже при аварийном завершении.

```xml
<?xml version='1.0' encoding='utf-8'?>
<session user="user" started="2026-09-18T13:48:38">
  <event time="2026-09-18T13:48:38" user="user" command="ls" status="ok">
    <arguments>-l /etc</arguments>
  </event>
  <event time="2026-09-18T13:48:43" user="user" command="wget"
         status="error">
    <arguments />
    <error>wget: команда не найдена</error>
  </event>
</session>
```

Каждое событие дополнительно содержит имя пользователя реальной
операционной системы и, при неудачном выполнении, сообщение о
возникшей ошибке.

### Виртуальная файловая система

Источником VFS служит ZIP-архив, указанный параметром `--vfs`. Архив
открывается только на чтение: его содержимое целиком переносится в
дерево узлов в оперативной памяти. **Архив не распаковывается и не
изменяется** — все дальнейшие операции выполняются исключительно над
деревом в памяти.

Двоичные данные хранятся в архиве в кодировке base64: такие элементы
имеют суффикс `.b64`, который снимается при загрузке, а содержимое
восстанавливается в исходные байты.

Исходные образы VFS лежат в каталоге `vfs` в виде обычных деревьев
файлов; ZIP-архивы собираются командой `make vfs` в каталог `build`
и в репозитории не хранятся:

| Образ | Содержимое |
|-------|-----------|
| `minimal` | Один файл в корне |
| `simple` | Несколько файлов в корневом каталоге |
| `deep` | Не менее трёх уровней вложенности, файл в base64 |

При успешной загрузке эмулятор печатает и записывает в журнал
краткое описание образа, например:

```text
VFS «deep» загружена в память: каталогов 10, файлов 7
```

Ошибки загрузки (файл не найден, неверный формат) приводят к
сообщению об ошибке и завершению работы с кодом возврата 1.

### Стартовые скрипты эмулятора

Стартовый скрипт — текстовый файл с расширением `.vsh`, содержащий
по одной команде эмулятора в строке. Пустые строки и строки,
начинающиеся с `#`, пропускаются.

При выполнении скрипта на экран выводится как ввод, так и вывод
команд, что имитирует диалог с пользователем. **Выполнение
останавливается на первой ошибке**: эмулятор печатает имя файла,
номер строки и описание ошибки, после чего завершает работу с кодом
возврата 1.

Готовые скрипты находятся в папке `startup`:

* `stage2_basic.vsh` — успешное выполнение всех команд;
* `stage2_error.vsh` — остановка на первой ошибке;
* `stage3_all.vsh` — все команды этапов 1–3, ошибочная команда стоит
  последней, поскольку выполнение на ней прекращается;
* `stage4_commands.vsh` — все режимы команд `ls`, `cd`, `history` и
  `echo` на образе с глубокой вложенностью.

### Обработка ошибок

Сообщения об ошибках выводятся в стандартный поток ошибок в виде
`ошибка: <описание>`. В интерактивном режиме диалог продолжается, при
выполнении скрипта — прекращается.

Предусмотрены ошибки:

* неизвестная команда;
* неверное число аргументов команды;
* недоступный или отсутствующий файл стартового скрипта;
* неизвестный параметр командной строки;
* образ VFS не найден или имеет неверный формат;
* путь внутри VFS не существует или ведёт через файл.

## Сборка проекта и запуск тестов

Внешние зависимости не требуются, достаточно Python 3.10 и новее.

```bash
make vfs                       # собрать ZIP-образы VFS в build
./run.sh --vfs build/deep.zip  # запуск эмулятора
make run ARGS='--log build/s.xml'   # запуск с параметрами
make test                      # запуск модульных тестов
make clean                     # удаление временных файлов
```

Скрипты реальной ОС для проверки эмулятора находятся в папке
`scripts`:

```bash
./scripts/stage2_defaults.sh   # каждый параметр по отдельности
./scripts/stage2_full.sh       # все параметры сразу
./scripts/stage2_errors.sh     # обработка ошибок параметров
./scripts/stage3_vfs.sh        # все варианты образов VFS
./scripts/stage3_errors.sh     # обработка ошибок загрузки VFS
./scripts/stage4_commands.sh   # все режимы ls, cd, history и echo
```

### Интерактивный режим

```text
$ make vfs
$ ./run.sh --vfs build/deep.zip
=== Параметры запуска эмулятора ===
Путь к VFS: build/deep.zip
Путь к лог-файлу: не задан
Путь к стартовому скрипту: не задан
===================================
VFS «deep» загружена в память: каталогов 10, файлов 7
deep:/$ ls
etc
home
var
deep:/$ cd home/user/docs
deep:/home/user/docs$ ls -l
drwxr-xr-x       0 archive
-rw-r--r--      60 report.txt
deep:/home/user/docs$ cd ../..
deep:/home$ echo Проверка команды echo
Проверка команды echo
deep:/home$ history 2
   5  cd ../..
   6  echo Проверка команды echo
deep:/home$ ls /home/nobody
ошибка: /home/nobody: нет такого файла или каталога
deep:/home$ exit
Выход из эмулятора.
```

### Выполнение стартового скрипта

```text
$ ./run.sh --vfs build/minimal.zip --script startup/stage2_error.vsh
minimal:/$ ls /var
ошибка: startup/stage2_error.vsh:2: /var: нет такого файла или каталога
        (выполнение остановлено)
```
